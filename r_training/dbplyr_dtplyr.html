Setup

Create a new project, install packages if needed, attach the stringr, tidytext, and dplyr packages, and create some simple data:

# install.packages("dplyr")
# install.packages("dtplyr")
# install.packages("dbplyr")
# install.packages("palmerpenguins")
# install.packages("DBI")

library(dplyr)
library(dtplyr)
library(dbplyr)
library(palmerpenguins)

What?

  • dplyr is great! Easy to read and write, nicely compatible with other R tools, with a chunky user-base and nice docs
  • dplyr is also a) slow and b) holds your data in memory
  • that means that when your data gets big (or complicated, or remote,…) dplyr becomes slow and annoying
  • the dream: write dplyr, but execute something else more capable of tackling the big stuff
  • both dtplyr and dbplyr are both flavours of execute something else while writing dplyr
    • dtplyr = data.table
    • dbplyr = SQL

It’s actually a great system if you have the time to spend getting comfortable with it: really a very concise way of writing SQL-ish expressions. But, it’s not easy to improvise, and it really does take a bit of time to get happy working in this way, especially if you’ve spent lots of time writing nice literate tidyverse code.

dbplyr

dbplyr takes a similar approach to dtplyr, but has much more flexibility about source data. You can easily e.g. connect to a remote server or similar using DBI. That’s largely outwith the scope of this session, so we’ll create an in-memory SQLite database as a demonstration of how this might be used to manage large datasets in R:

con <- DBI::dbConnect(RSQLite::SQLite(), dbname = ":memory:") # creates a SQLite db

copy_to(con, penguins, "pengs") # adds the penguins dataset as a table called pengs
